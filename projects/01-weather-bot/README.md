# 🌤️ Weather Bot (n8n + PostgreSQL)

Телеграм-бот, который показывает погоду и присылает уведомления по расписанию. Основная фишка — поддержка точного геокодинга (вплоть до деревень и районов) и кэширование координат, чтобы не спамить внешние API.

## 🚀 Что умеет
*   **Инлайн-меню:** Выбор региона, города и района через кнопки.
*   **База ГАР:** В проекте используется спарсенная база ФНС (ГАР/ФИАС). Загружены города, районы, села, деревни и пригороды. **Улицы исключены**, чтобы не раздувать базу.
*   **Умный геокодинг (Fallback):** Если в БД нет широты/долготы для населенного пункта, бот сам ищет их через Nominatim (OSM) или Open-Meteo, а затем сохраняет в базу. Повторный запрос летает моментально.
*   **Уведомления:** Отдельный фоновый процесс проверяет расписание и шлет погоду с учетом часового пояса юзера.

## 🛠️ Стек
*   **n8n** (self-hosted)
*   **PostgreSQL** (храним юзеров, локации, кэш, настройки)
*   **API:** Open-Meteo (погода), Nominatim (геокодинг)
*   **Python** (обработка исходных XML баз)
*   **Code (JS):** Логика склонения падежей, fallback-геокодинга и сборки клавиатур.

## 🏗️ Архитектура воркфлоу
Проект разделен на два независимых воркфлоу (Separation of Concerns):
1. **`workflow-user-interaction.json` (Interactive Bot)** — отвечает за вебхуки от Telegram, обработку нажатий кнопок, работу с меню и выдачу погоды «по запросу».
2. **`workflow-cron-notifications.json` (Background Worker)** — фоновый процесс. Запускается по `Schedule Trigger`, лезет в базу, проверяет чей часовой пояс подошел к времени уведомления, и рассылает прогнозы. 

Такое разделение позволяет перезапускать или чинить уведомления, не задевая работу самого бота.

## 🗄️ ETL: Как парсилась база (400 ГБ)
Исходная база ГАР весит 400 ГБ и состоит из XML-файлов, разбитых по регионам. Загрузить её в базу «в лоб» невозможно. Для обработки был написан скрипт **`parse_gar.py`**.

**Особенности парсера:**
*   **Потоковое чтение:** `xml.etree.ElementTree.iterparse` позволяет читать гигабайты данных, не переполняя оперативную память.
*   **Отказоустойчивость:** Скрипт запоминает, какие регионы уже обработаны. При сбое работу можно продолжить с того же места (флаг `--force` пересоздает файлы).
*   **Атомарная запись:** Данные пишутся во временный `.tmp` файл, чтобы не оставить «битый» CSV при внезапном отключении питания.
*   **Очистка:** Из базы исключены улицы, оставлены только населенные пункты (города, районы, села, деревни).

**Запуск парсера:**
```bash
# Для Windows
python parse_gar.py --gar C:\path\to\gar_xml --out C:\path\to\csv --merge

# Для Linux/macOS
python3 parse_gar.py --gar ./gar_xml --out ./output/csv --merge
